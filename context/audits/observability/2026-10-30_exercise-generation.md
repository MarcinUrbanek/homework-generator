# Observability audit — exercise-generation (2026-10-30)

> Dirty tree: only `.github/.10x-cli-manifest.json` was modified (tooling, not app code). The app is **not deployed yet**; this is a pre-launch audit.

## 1. TL;DR

- **Every exercise API handler catches everything and returns a typed JSON error without logging.** Astro's own boundary (the only place that would log a stack) never sees the error. An OpenRouter outage, a DB outage and a bug in our own parser all end up as an identical `502 PROVIDER_FAILURE` / `500 PERSISTENCE_FAILURE` with **nothing in the logs** (runtime-proven: P4, P6).
- **The service layer turns errors into status enums and drops the cause.** `profile-unavailable`, `unavailable` and `VerificationPersistenceError()` carry no code or message, and **`cause` is used 0 times in `src/`**. A Supabase outage during teacher authorization reaches the teacher as **403 "cannot confirm teacher permissions"**.
- **Middleware treats a Supabase auth failure as "anonymous"**: every protected page redirects to sign-in with no log (runtime-proven: P5b, `302` after 2 s, console empty).
- **The only 3 log lines in the app are constant strings** (`exercise_generation_admission_unavailable` / `…release_unavailable`). There's no code, no status and no reservation id, so a stuck reservation (teacher blocked with 429s) can't be diagnosed.
- **Code outside any boundary leaves nothing**: an unhandled rejection (P7) prints nothing, a `waitUntil` rejection (P8) prints no message, and a throw after SSR streaming starts (P10) returns **`200` with an empty body and no log**. There's no client-side handler or React error boundary.
- **The most important consequence:** if OpenRouter changes its response shape or revokes the key on launch day, every teacher gets "Nie udało się wygenerować zadań", and Workers Logs show only `POST /api/exercises/request 502`, with no clue whether it's the provider, the key, the model output, or our code.

## 4. Systemic root causes

1. **Handler-level catch-alls pre-empt the only stack-logging boundary.** Each exercise route wraps its body in a `try/catch` that maps _any_ error, including our own `TypeError`s and Zod parse bugs, to a public error code and returns it without logging: `src/pages/api/exercises/request.ts:157-164`, `verify.ts:326-355`, `approve.ts:122-131`, `saved.ts:171-190`. The generator does the same one level down: `makeAttempt`'s catch converts every non-timeout error into `PROVIDER_FAILURE` (`src/lib/services/openrouter-exercise-generator.ts:261-270`). _Why it exists:_ stable, user-friendly Polish error contracts (good). _What's missing:_ a log of the original error before mapping. _Explains:_ EG-1, EG-3, EG-7, EG-8, EG-9.
2. **Status-enum service results with no cause.** Services return `{ status: "profile-unavailable" }` / `"unavailable"` or throw bare `new VerificationPersistenceError()` / `Object.assign(new Error("…failed"), { code })`. The Supabase error's message, details and hint are discarded at the first boundary: `src/lib/services/teacher-authorization.ts:27-43`, `exercise-generation-admission.ts:30-50,56-71`, `verify.ts:101-104,153-156`, `approve.ts:51-53`, `saved.ts:119-121`. 0 uses of `cause` in `src/`. _Explains:_ EG-2, EG-4, EG-5, EG-6, EG-7, PL-6.
3. **Constant-string logging as the privacy strategy.** The 3 existing logs (`request.ts:135,172,176`) avoid PII by dropping _everything_, including non-PII diagnostics (Postgres code, HTTP status, reservation id, stage). _Explains:_ EG-4, EG-5, PL-9.
4. **Middleware converts auth errors into identity.** `src/middleware.ts:14-20` ignores `error` from `getUser()`, and `src/lib/supabase.ts:6-9,24-27` returns `null` on missing config. Both become `user = null` → redirect. _Explains:_ PL-1, PL-6.
5. **No boundary for code outside the request/response path.** Browser islands have no error boundary or global handler (`src/layouts/Layout.astro`), client fetch failures are caught into UI text (`RequestExercisesForm.tsx:76,116,146`), and Astro's boundary doesn't cover floating promises, `waitUntil` or post-first-byte streaming (P7, P8, P10). _Explains:_ EG-11, EG-12, PL-2, PL-4, PL-5.

## 6. Recommended fix order

1. **Middleware error boundary + shared `logError` helper** (PL-3, PL-9; prerequisite for the rest). Wrap `next()` in `src/middleware.ts` with a catch that `console.error`s `{ route, userId, cf-ray }` + the error object and then re-throws. Add `src/lib/log-error.ts`: a structured line with the error object (keeps stack + `[cause]`, as P9 proves). _Constraint:_ log user **id**, never email; never log exercise text or provider bodies.
2. **Log before mapping in the 4 exercise handlers + generator** (closes EG-1, EG-3, EG-7, EG-8; same helper fixes PL-8). One call in each outer `catch`. Stop wrapping non-provider errors as `PROVIDER_FAILURE` in `makeAttempt`. _Constraint:_ keep the public error codes and messages unchanged (tests assert them).
3. **Attach `cause` and the PostgREST code at service boundaries** (EG-2, EG-4, EG-5, EG-6, EG-9). Make `profile-unavailable` → 503. Add a `reason` to admission/release `unavailable`. Add `status` to the OpenRouter error.
4. **Middleware auth-error handling + null-client logging** (PL-1, PL-6). Distinguish "no session" from "auth unreachable".
5. **Client error reporting route + island boundary** (PL-5, EG-11, EG-12).
6. **Guardrails for latent gaps** (PL-2, PL-4, EG-10): review/lint rules for `.astro` awaits and un-caught `waitUntil`, plus a batch-quality info line.

Re-run the probe suite (see §8) after steps 1–4. The target is P4, P5b and P6 moving from _missed_ to _good_ (P9-shaped output), and P1 showing `[cause]`.
